## 1. 系统概览

### 1.1 研究背景与动机

DocAgent 是一个面向**超长文档多模态理解**的多智能体协作框架，模拟人类阅读学术论文的过程：

- **挑战1**: 现有 LLM 上下文窗口有限（4K-32K tokens），无法处理百页以上的文档
- **挑战2**: 文档包含文本、图表、公式等多模态信息，需要综合理解
- **挑战3**: 简单的 Map-Reduce 分块方法会丢失全局逻辑连贯性

### 1.2 核心思想

```
┌─────────────────────────────────────────────────────────────┐
│                        人类阅读过程                           │
├─────────────────────────────────────────────────────────────┤
│ 1. 浏览大纲 (Outline Browsing) → 确定重点章节                │
│ 2. 精读章节 (Deep Reading) → 提取细节信息                    │
│ 3. 多模态理解 (Multi-modal) → 分析图表与正文一致性            │
│ 4. 交叉验证 (Cross-checking) → 对比不同来源的信息            │
│ 5. 全局推理 (Global Reasoning) → 检查逻辑一致性              │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    DocAgent 系统设计                         │
├─────────────────────────────────────────────────────────────┤
│ 1. 树状大纲 (Structured Outline) → XML 格式的层次化结构      │
│ 2. 工具化接口 (Tool-based Interface) → 动态检索章节/图表      │
│ 3. 多智能体协作 (Multi-agent) → 规范/逻辑/视觉分工审查        │
│ 4. 记忆银行 (Memory Bank) → 跨章节事实存储与冲突检测          │
│ 5. 层次化审查 (Hierarchical) → Map-Reduce 全局一致性验证     │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 系统特点

| 特性             | 传统方法           | DocAgent                    |
| ---------------- | ------------------ | --------------------------- |
| **文档长度支持** | ≤ 10K tokens       | **100+ 页**（短上下文迭代） |
| **多模态理解**   | 仅文本 or 简单 OCR | **视觉模型验证图表**        |
| **全局一致性**   | 分块丢失上下文     | **Map-Reduce + 记忆银行**   |
| **误差修正**     | 依赖原始提取       | **OCR 增强 + 视觉交叉验证** |

### 3.2 数据结构设计

#### 3.2.1 DataFrame Schema (data.pkl)

```python
df = pd.DataFrame({
    'style': str,       # 元素类型: "Heading 1", "Normal", "Image", "Table", "Page_Start"
    'table_id': int,    # 表格/图片ID 或 页码
    'para_text': Any    # 文本内容 或 字典(图片/表格元数据)
})
```

**示例数据**:

```
   style          table_id   para_text
0  Page_Start     1          None
1  Title          None       "基于深度学习的目标检测研究"
2  Heading 1      None       "第1章 绪论"
3  Normal         None       "近年来，深度学习技术..."
4  Heading 2      None       "1.1 研究背景"
5  Normal         None       "目标检测是计算机视觉..."
6  Image          0          {'path': 'figures/0.png', 'alt_text': 'YOLO架构'}
7  Caption        None       "图 1-1 YOLO网络结构"
8  Table          0          "编号,模型,准确率\n1,YOLO,89.3\n2,Faster R-CNN,92.1"
```

#### 3.2.2 XML Tree 结构

DocReader 将 DataFrame 转换为层次化 XML 树：

```xml
<Document>
  <Section section_id="1" start_page_num="5" end_page_num="12">
    <Heading>第1章 绪论</Heading>
    <Section section_id="1.1" start_page_num="5" end_page_num="7">
      <Heading>1.1 研究背景</Heading>
      <Paragraph page_num="5">近年来，深度学习技术...</Paragraph>
      <Image image_id="0" page_num="6">
        <Alt_Text>YOLO架构</Alt_Text>
        <Caption>图 1-1 YOLO网络结构</Caption>
      </Image>
    </Section>
    <Section section_id="1.2" start_page_num="7" end_page_num="12">
      <Heading>1.2 国内外研究现状</Heading>
      <Paragraph page_num="7">目标检测方法可分为...</Paragraph>
      <CSV_Table table_id="0" page_num="8">
        编号,模型,准确率
        1,YOLO,89.3
        2,Faster R-CNN,92.1
      </CSV_Table>
    </Section>
  </Section>
</Document>
```

**设计优势**:

- **层次清晰**: Section 嵌套反映文档结构（支持最多10层）
- **页码标注**: 每个元素都记录 `page_num`，便于定位
- **灵活查询**: 支持 XPath 式的精确检索

#### 4.2.2 视觉验证机制（创新点）

**问题背景**: Adobe PDF 提取器可能漏识别章节标题（如加粗但无明确 Heading 标记）。

**解决方案**:

1. **触发条件**:
   - issue_type = "规范性"
   - suggestion 包含关键词: "缺少", "丢失", "不连续", "页码"
2. **验证流程**:
   ```python
   def verify_with_vision(issue):
       page_num = issue['page']
       page_image = doc_reader.get_page_image(page_num)

       prompt = """
       问题: {issue['suggestion']}
       请查看页面截图，判断该问题是否为"误报"：
       - 若页面确实有该章节标题 → is_false_positive = True
       - 若页面确实缺失 → is_false_positive = False
       输出: {"is_false_positive": bool, "reason": str}
       """

       response = vision_model.chat(prompt, page_image)
       if response['is_false_positive']:
           return None  # 移除误报
       return issue
   ```
3. **模型选择**: Qwen3-VL-Flash (多模态大模型)

### 4.3 Agent B: 逻辑审查 (Hierarchical Logic Review)

#### 4.3.1 层次化审查流程 (Map-Reduce)

```
┌──────────────────────────────────────────────────────────────┐
│        Agent B: 层次化逻辑审查 (Map-Reduce 架构)              │
└──────────────────────────────────────────────────────────────┘
                            │
        ┌───────────────────▼───────────────────┐
        │  Phase 1: 章节选择 (智能筛选)          │
        │  • LLM 分析 Outline XML               │
        │  • 返回最重要的 8 个 section_id        │
        │  • 避免处理冗余的附录/参考文献          │
        └───────────────────┬───────────────────┘
                            │
        ┌───────────────────▼───────────────────────────────────┐
        │  Phase 2: Map - 分章节审查 (Local Review)             │
        ├───────────────────────────────────────────────────────┤
        │  For each chapter in selected_sections:              │
        │    ┌─────────────────────────────────────────────┐   │
        │    │  输入: get_section_content(section_id)      │   │
        │    │   • 章节完整 XML (最多12000字符)            │   │
        │    └────────────────┬────────────────────────────┘   │
        │                     │                                 │
        │    ┌────────────────▼────────────────────────────┐   │
        │    │  Prompt: local_chapter_review_prompt        │   │
        │    │  任务:                                       │   │
        │    │   1. 微观逻辑检查 (论证跳跃/前后矛盾)        │   │
        │    │   2. 语言学术化 (口语表达/词汇不当)          │   │
        │    │   3. 段落衔接 (连贯性)                       │   │
        │    │   4. **提取章节摘要** (核心论点+数据)        │   │
        │    └────────────────┬────────────────────────────┘   │
```

#### 4.4.2 三页窗口策略（创新点）

**问题背景**: 图片的 Caption 可能跨页（图在第N页末尾，Caption在第N+1页开头），导致视觉模型看不到完整上下文。

**解决方案**:

```python
pages_to_fetch = [current_page - 1, current_page, current_page + 1]
page_labels = ["前一页", "当前页", "后一页"]

messages = [
    {"role": "system", "content": vision_prompt},
    {"role": "user", "content": [
        {"type": "text", "text": "【目标图片】："},
        {"type": "image_url", "image_url": target_image},
        {"type": "text", "text": "【前一页：Page N-1】"},
        {"type": "image_url", "image_url": page_n_minus_1},
        {"type": "text", "text": "【当前页：Page N】"},
        {"type": "image_url", "image_url": page_n},
        {"type": "text", "text": "【后一页：Page N+1】"},
        {"type": "image_url", "image_url": page_n_plus_1}
    ]}
]
```

**Prompt 设计（引导式三步推理）**:

```
步骤1：视觉定位
- 观察【目标图片】的形状、内容、颜色
- 在三页截图中找到该图片出现在哪一页

步骤2：依次解析三页内容
- 前一页（Page N-1）: 是否包含目标图片？是否有相关Caption/正文？
- 当前页（Page N）: 是否包含目标图片？是否有相关Caption/正文？

- 汇总从三页中提取的真实Caption和正文描述
```


### 5.2 XML Tree 构建逻辑

```python
# 核心算法: 基于 Heading 层级构建嵌套 Section
def build_xml_tree(df):
    root = ET.Element("Document")
    stack = [(root, 0)]  # (当前节点, Heading级别)
    section_id_stack = []

    for index, row in df.iterrows():
        if row['style'].startswith('Heading'):
            heading_num = int(row['style'].split()[1])  # Heading 1 → 1

            # 处理层级关系
            while heading_num <= stack[-1][1]:  # 回退到更高层级
                stack.pop()
                section_id_stack.pop()

            # 创建新 Section
            if heading_num == stack[-1][1]:  # 同级
                section_id_stack[-1] += 1  # 1.1 → 1.2
            else:  # 更低级
                section_id_stack.append(1)  # 1 → 1.1

            section_id = '.'.join(map(str, section_id_stack))
            curr_node = ET.SubElement(stack[-1][0], "Section",
                                     section_id=section_id,
                                     start_page_num=curr_page)

            heading = ET.SubElement(curr_node, "Heading")
            heading.text = row['para_text']

            stack.append((curr_node, heading_num))

        elif row['style'] == 'Normal':
            para = ET.SubElement(stack[-1][0], "Paragraph", page_num=curr_page)
            para.text = row['para_text']

        # ... (处理 Image, Table, Caption 等)

    return root
```

| **PaddleOCR**          | OCR 增强标题检测 | PaddlePaddle 3.0 |
| **PyMuPDF (fitz)**     | PDF 页面渲染     | ≥ 1.23           |
| **DeepSeek-V3**        | 文本审查 LLM     | deepseek-chat    |
| **Qwen3-VL-Flash**     | 视觉理解模型     | 多模态 LLM       |
| **XML + XPath**        | 文档结构表示     | ElementTree      |
| **Pandas**             | 数据处理         | ≥ 1.5            |

### 7.2 创新点总结

#### 1. **OCR 增强的标题修正**

- **问题**: Adobe 提取器对非标准格式的标题（加粗但无明确标记）识别率低
- **方案**:
  1. PaddleOCR 识别所有文本行 + 字体大小/粗体启发式规则
  2. 对比 OCR 与 Adobe 结果，交叉验证
  3. 自动修正: 补充遗漏标题 / 降级误识别标题

#### 2. **视觉验证的误报过滤**

- **问题**: 文本分析发现"缺少章节4.2"，但可能是 PDF 解析器错误
- **方案**:
  1. 触发条件: 涉及"缺失"/"编号"的规范性问题
  2. 调用 Qwen-VL 查看页面截图
  3. 判断: 若页面确实有 → 移除误报; 若确实缺失 → 保留问题

#### 3. **三页窗口的多模态输入**

- **问题**: 图片 Caption 可能跨页，视觉模型看不到完整上下文
- **方案**:
  - 输入: 目标图片 + 前一页截图 + 当前页截图 + 后一页截图
  - Prompt 引导: 三步推理（定位 → 解析 → 判断）

#### 4. **层次化 Map-Reduce 逻辑审查**

- **问题**: 直接输入整个文档超出上下文窗口，分块又丢失全局逻辑
- **方案**:
  1. **Map 阶段**: 分章节审查 → 提取摘要（浓缩信息）
  2. **Reduce 阶段**: 基于摘要进行全局一致性检查
  3. 摘要长度: ~200字/章节 → 8章节只需1600字符

#### 5. **细粒度事实存储与冲突检测**

- **问题**: Map-Reduce 只能检测宏观矛盾，微观数值冲突难以发现
- **方案**:
  - 提取: 实体（人名/机构）、数值（准确率/样本数）、时间、论断
  - 存储: 跨章节索引（key → [value1, value2, ...]）
  - 检测: 同一 key 的不同 value → 冲突报警

#### 6. **工具化的动态检索接口**

- **问题**: LLM 无法预知需要哪些内容，一次性输入大纲+正文 → 浪费 tokens
- **方案**:
  - 提供工具: `search()`, `get_section_content()`, `get_image()`
  - LLM 按需调用: 先看大纲 → 定位章节 → 深度检索
  - 节省成本: 只检索相关内容（类似人类"跳读"）

```bash
python review_runner.py --doc-id bylw

python run_experiment.py \
    --preprocessed-data-dir ./preprocess/processed_output/ \
```

### 8.3 性能与成本分析

**处理一篇50页本科论文的典型数据**:

| 阶段                  | 耗时   | API 调用次数 | Tokens 消耗            |
| --------------------- | ------ | ------------ | ---------------------- |
| **预处理**            | ~2分钟 | 1 (Adobe)    | 免费额度               |
| **OCR 增强**          | ~30秒  | 0 (本地)     | 0                      |
| **规范性审查**        | ~10秒  | 1            | ~8K tokens             |
| **逻辑审查 (Map)**    | ~80秒  | 8            | ~96K tokens (12K/章节) |
| **逻辑审查 (Reduce)** | ~15秒  | 1            | ~6K tokens             |
| **视觉审查**          | ~120秒 | 20           | ~40K tokens (2K/图)    |
| **总计**              | ~5分钟 | 31           | ~150K tokens           |

**成本估算**:

- DeepSeek-V3: $1/M tokens → **$0.15**
- Qwen3-VL-Flash: $0.5/M tokens → **$0.02**
- **总成本: < $0.2**（约人民币1.5元）

## 9. 系统优势与局限性

### 9.1 系统优势

✅ **长文档支持**: 通过 Map-Reduce 和动态检索，可处理100+页文档  
✅ **多模态理解**: 集成视觉模型，实现图文一致性验证  
✅ **误差修正**: OCR 增强 + 视觉验证双重修正 PDF 解析误差  
✅ **全局一致性**: 记忆银行机制检测跨章节矛盾  
✅ **高性价比**: 短上下文迭代，成本低（< $0.2/篇）  
✅ **可解释性**: 输出完整的 <thinking> 推理过程

### 9.2 局限性与未来工作

❌ **依赖 PDF 质量**: 扫描版 PDF 效果较差（需高质量 OCR）  
❌ **数学公式理解**: 当前未专门处理 LaTeX 公式  
❌ **跨语言支持**: 主要面向中文论文（英文需调整 Prompt）  
❌ **复杂表格**: 嵌套表格可能解析失败  
❌ **实时性**: 串行处理，无法实时审查（可优化为流式）

**未来改进方向**:

1. 集成 MathPix/LaTeX OCR 处理公式
2. 支持多轮对话式审查（用户交互修正）
3. 引入专家评分数据集，微调审查模型
4. 扩展到其他文档类型（合同、报告、专利）

## 10. 总结

DocAgent 是一个**面向长文档多模态理解的多智能体协作框架**，核心创新在于：

1. **结构化表示**: PDF → XML 树 + 页面图像
2. **智能修正**: OCR 增强 + 视觉验证双重修正
3. **层次化推理**: Map-Reduce 架构 + 记忆银行
4. **多模态融合**: 文本审查 + 图文一致性验证
5. **工具化接口**: 动态检索 + 按需访问

该系统在 **EMNLP 2025** 上发表，实验表明在文档 QA 任务上接近人类水平，同时保持短上下文长度（< 8K tokens/次调用）。
