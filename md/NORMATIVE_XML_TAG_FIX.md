# 规范性审查误判修复方案

## 问题描述

论文正文中经常会出现对章节的描述，例如：
```
本文共分为6章，第1章绪论，第2章需求分析，第3章系统设计...
```

这些是**正文中对标题的引用**，不是真实标题。但 AI 审查会误判为"章节编号格式不统一"（例如：报告"'第1章 绪论'与'1 绪论'格式不一致"）。

##解决方案

### 核心思路
**预处理后的 XML 大纲已经区分了标题和正文**：
- 真实标题：出现在 `<Heading>` 或 `<Title>` 标签中
- 正文内容：出现在 `<Paragraph>` 标签中

**只需在 Prompt 中说明：只检查 `<Heading>` 标签，忽略 `<Paragraph>` 标签即可。**

###实施方法

在 `agent/prompts.py` 的 `normative_prompt` 中第 46 行后添加以下内容：

```python
【核心规则：如何识别真实标题 vs 正文引用】避免误判的关键！

预处理后的XML大纲已明确区分标题和正文：
- 真实标题：出现在 <Heading> 或 <Title> 标签中
- 正文内容：出现在 <Paragraph> 标签中

检查规则（严格遵守）：
1. 只检查 <Heading> 和 <Title> 标签中的文本，这些是真实章节标题，检查编号格式是否统一。
2. 完全忽略 <Paragraph> 标签中的章节引用，即使看到"第1章 绪论"等文本，这只是正文引用，不是真实标题。禁止报告"'第1章'与'1 绪论'格式不统一"。
3. 特殊情况：如果 <Heading> 标签中出现"第X章"格式，而大纲中其他 <Heading> 都是"1"、"2"格式，说明PDF解析器误判，此时才报告格式不统一。

判断标准：看XML大纲中所有 <Heading> 标签的整体编号风格，<Paragraph> 中的"第X章"永远不报告。
```

### 具体位置

在 `agent/prompts.py` 文件中：
- **位置**：第 46 行（`5. **忽略题目审查**...`）后面
- **在"步骤："之前**插入上述内容

### 验证方法

修改后，使用包含"第1章 绪论"等正文描述的论文测试，确认不再报告格式不统一错误。

### 预期效果

✅ **正确做法**：
```xml
<Heading>1 绪论</Heading>
<Heading>2 需求分析</Heading>
<Paragraph>本文结构如下：第1章绪论，第2章需求分析...</Paragraph>
```
→ 判断：格式统一（`<Heading>` 都是数字格式），`<Paragraph>` 中的"第X章"被忽略

❌ **过去的误判**：
```xml
<Heading>1 绪论</Heading>
<Paragraph>第1章绪论，概括了...</Paragraph>
```
→ 误判："章节编号格式不统一：'1 绪论'与'第1章 绪论'格式不一致"
→ 现在：`<Paragraph>` 中的文本被完全忽略，不再误判

⚠️ **需要报告的情况**（PDF 解析错误）：
```xml
<Heading>1 绪论</Heading>
<Heading>第3章 系统设计</Heading>
```
→ 报告："章节编号格式不统一：`<Heading>` 中混用了数字格式（'1 绪论'）和中文格式（'第3章 系统设计'），建议统一使用数字格式"

## 优点

1. ✅ **100% 准确**：基于 XML 标签，不依赖 LLM 语义理解
2. ✅ **实现简单**：只需修改 Prompt
3. ✅ **无副作用**：不影响其他检查逻辑
4. ✅ **利用预处理**：充分利用了已有的结构化信息
