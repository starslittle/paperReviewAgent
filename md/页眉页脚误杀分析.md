# 页眉页脚误杀正文 — 原因分析与改进方向

本文档说明当前流程中**正文被误判为页眉/页脚**的主要原因，便于后续改代码或调参时有的放矢。

---

## 一、两套判断逻辑分别在哪里

| 阶段      | 文件                                     | 作用                                                                                             |
| --------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 预处理    | `preprocess/2_process_extracted_data.py` | 从 MinerU 的 middle.json 生成 data.pkl，给部分块打上 **Header/Footer** 样式                      |
| 审查/过滤 | `agent/doc_agent.py`                     | 建“页眉页脚索引”，在逻辑审查等环节用 **\_is_header_footer()** 过滤段落，避免把页眉页脚当正文审查 |

两处都会导致“正文被当成页眉页脚”：要么在 2_process 就被标成 Header/Footer，要么在 doc_agent 被纳入索引后在过滤时被误杀。

---

## 二、误杀原因 1：预处理阶段（2_process_extracted_data.py）

### 2.1 候选条件（满足才会进入“候选”）

- 只处理 **type 为 text/paragraph** 的块。
- 内容 **归一化后长度 ≤ 80 字**。
- 必须有 **有效 bbox**（长度≥4），且能算出该页的 **page_height**。
- **位置**：
  - 块下边界 `y2 <= page_height * 0.12` → 进入页眉候选；
  - 块上边界 `y1 >= page_height * 0.88` → 进入页脚候选。
- **重复度**：同一段归一化文本在 **≥ 60% 的页** 都出现在顶/底区域，才最终记为页眉/页脚候选。

### 2.2 误杀正文的典型情况

1. **bbox 偏差或页高不准**
   - MinerU 有时把正文块 y 偏小，或 page_height 推断偏大，导致本在页面中部的段落落在“顶 12%”内。
   - 若该段较短且在多页出现（如每章开头的“本章介绍…”），就会同时满足“顶区 + 多页重复”，被标成 Header。

2. **短句在多页顶/底重复**
   - 例如：每章第一段都是“本章主要介绍…”“本节讨论…”，若解析顺序或 bbox 让它们落在顶 12%，且文档有 5 页以上，60% 页数约 3 页，很容易达到重复阈值，被当成页眉。

3. **页脚区误判**
   - 正文最后一段若在多数页都落在 bottom 12%（例如每章末的“小结”段落），且长度 ≤80，可能被标成 Footer。

---

## 三、误杀原因 2：Agent 阶段（doc_agent.py）

### 3.1 页眉页脚索引怎么建

- 遍历 XML 里 **Paragraph / Heading / Title / Caption / Header / Footer** 的 **text**，按 **page_num** 归到每页。
- **per_page_texts[page]**：该页所有上述节点文本的**文档顺序**列表（不是按 bbox 排序）。
- **top_bottom_by_page[page]**：取该页**前 2 条 + 后 2 条**文本（`top_bottom_n=2`），视为“可能页眉/页脚”的集合。
- **repeated_texts**：在 **≥ 3 页** 都出现过的文本，全部记入“页眉页脚索引”。
- **regex_matches**：与下面正则匹配的文本也全部记入索引。

### 3.2 正则（过宽，易误伤正文）

```text
(第\s*\d+\s*页|页码|学院|专业|指导教师|学校|论文|本科|毕业|\d{4}\s*年)
```

- 正文里常见词如 **“学校”“论文”“本科”“毕业”** 以及 **“2024年”** 等，只要出现就会被视为页眉页脚特征，整段被过滤，导致误杀。

### 3.3 误杀正文的典型情况

1. **“每页前 2 / 后 2”按文档顺序，不是按版面**
   - 若 XML 里该页前两个节点是：章节标题 + 第一段正文，它们会被算进 **top_bottom_by_page**。
   - 若这段正文里又含有“学校”“论文”“本科”等词（匹配 regex），`_is_header_footer(text, page_num)` 会返回 True，该段在逻辑审查等环节被过滤，相当于误杀正文。

2. **重复 ≥3 页即视为页眉页脚**
   - 不区分是“真的页眉页脚”还是“章节小结、过渡句”等重复出现的正文。
   - 例如：“综上所述”“本章对…进行了总结”等在多页出现，会被记入索引，后续一律当页眉页脚过滤。

3. **正则过宽**
   - 凡含“学校、论文、本科、毕业、2024年”等词的段落，一律视为页眉页脚，即便在正文中间也会被过滤。

---

## 四、改进方向（供改代码时参考）

- **2_process_extracted_data.py**
  - 适当**提高重复比例**（如从 60% 提到 70%～80%），减少“多页重复的正文短句”被当成页眉页脚。
  - 对**顶/底区域**可略微收紧（如 top 10%、bottom 90%），减少 bbox 误差带来的误判。
  - 若 MinerU 提供区块类型（如 header/footer），可优先采用，本逻辑仅作补充。

- **doc_agent.py**
  - **正则收窄**：只保留强特征（如“第X页”“页码”“- 1 -”等），去掉“学校、论文、本科、毕业、XXXX年”等易出现在正文中的词，或改为“整段几乎全是这类词”才判为页眉页脚。
  - **重复阈值**：将 `repeat_threshold` 从 3 提高到 4～5，或要求“重复且出现在每页的 top/bottom 位置”才纳入索引（即结合位置，而不单凭多页出现）。
  - **top_bottom 与索引**：仅当文本**同时**在“该页 top/bottom 集合”内**且**（匹配正则 或 重复多页）时才判为页眉页脚，避免“仅因在每页前 2 条且含‘论文’就整段过滤”。

- **统一策略**
  - 若 2_process 已标出 Header/Footer，doc_agent 可**优先信任 XML 标签**，只对未标 Header/Footer 的段落用“重复 + 正则 + 位置”做二次判断，减少双重误杀。

---

## 五、小结

| 来源          | 易导致误杀的原因                                                                                               |
| ------------- | -------------------------------------------------------------------------------------------------------------- |
| **2_process** | 顶/底 12% 区域 + 60% 页重复 + bbox/页高不准 → 正文短句被标成 Header/Footer                                     |
| **doc_agent** | ① 每页前 2/后 2 条按文档顺序算，含正文 ② 重复 ≥3 页即入索引 ③ 正则过宽（学校/论文/本科/毕业/年份）→ 正文被过滤 |

后续若改代码，可优先：**收窄 doc_agent 的正则**、**提高重复阈值或结合位置再判**、以及**在 2_process 中提高重复比例或收紧顶底区域**，再视效果考虑是否信任 MinerU 的区块类型。
