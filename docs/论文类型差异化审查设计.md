# 论文类型差异化审查设计方案

## 1. 背景与需求

计算机毕业论文主要分为两大类：
- **算法类论文**：侧重算法改进、理论分析、性能优化
- **系统设计类论文**：侧重系统开发、功能实现、工程实践

两类论文的评审标准存在显著差异，需要设计差异化的审查策略。

---

## 2. 摘要部分的通用要求

### 2.1 内容结构（强制顺序）

摘要必须按照以下顺序展开：

1. **研究背景**（为什么做）
   - 说明研究问题、现状、意义
   - 例如："随着XX技术的发展，XX领域面临XX问题..."

2. **技术方案/功能介绍**（怎么做、做了什么）
   - 说明采用的技术栈、方法、系统架构
   - 说明实现的主要功能模块
   - 例如："采用Spring Boot + Vue架构，实现了XX、XX、XX等功能..."

3. **研究成果**（做得怎么样）
   - 说明测试结果、系统效果、性能指标
   - 例如："经测试，系统运行稳定，功能完备..."

### 2.2 关键词要求（严格检查）

- **中文摘要**：必须有"关键词："标识，**不少于4个**
- **英文摘要**：必须有"Keywords:"标识（注意K大写），**不少于4个**
- 关键词必须与论文主题相关，不得出现无关内容
- 关键词使用分号"；"或";"分隔

### 2.3 严重程度判断

- **High**: 缺少研究背景/技术方案/成果任一部分，关键词少于4个，关键词与主题完全无关
- **Medium**: 逻辑顺序混乱（如先讲技术再讲背景），关键词与主题部分不符
- **Low**: 表述不够简洁，过渡不够自然

---

## 3. 算法类论文 vs 系统设计类论文的差异

### 3.1 核心关注点对比

| 维度 | 算法类论文 | 系统设计类论文 |
|------|-----------|---------------|
| **核心目标** | 理论创新、算法优化、性能提升 | 功能实现、工程落地、用户体验 |
| **摘要重点** | 算法改进点、复杂度分析、性能指标 | 技术栈、功能模块、测试结果 |
| **实验要求** | 对比实验、消融实验、统计显著性 | 功能测试、用户测试、性能测试 |
| **图表类型** | 性能曲线图、对比柱状图、消融表 | 架构图、ER图、界面截图、流程图 |
| **创新性** | 算法改进、新模型提出 | 功能创新、技术整合 |

### 3.2 摘要部分的差异

#### 算法类论文摘要示例结构：
```
1. 研究背景：XX领域存在XX问题，现有算法存在XX不足
2. 技术方案：提出了基于XX的改进算法，通过XX方法优化了XX
3. 实验成果：在XX数据集上，准确率提升X%，时间复杂度降低到O(X)
关键词：算法名称；优化方法；性能指标；应用领域
```

#### 系统设计类论文摘要示例结构：
```
1. 研究背景：XX行业需求增长，现有系统存在XX问题
2. 技术方案：采用XX架构，基于XX技术栈，实现了XX、XX、XX等功能
3. 测试成果：经功能测试和性能测试，系统运行稳定，用户体验良好
关键词：技术栈；系统名称；核心功能；应用场景
```

#### 4.1.3 创建差异化的Prompt

在 `agent/prompts.py` 中添加：

```python
# ==================== 算法类论文摘要审查 ====================
abstract_review_algorithm = """
【算法类论文摘要特殊要求】

1. **内容结构**（严格顺序）：
   - 研究背景：说明XX领域问题，现有算法不足
   - 算法方案：提出的改进算法，核心创新点，优化方法
   - 实验成果：在XX数据集上的性能提升（准确率、召回率等），复杂度分析
   
2. **关键指标检查**：
   - 必须包含性能指标（准确率/召回率/F1/AUC等）
   - 必须说明在什么数据集上进行实验
   - 如果是改进算法，必须说明相比baseline的提升幅度
   
3. **关键词要求**：
   - 不少于4个
   - 必须包含：算法名称或方法名称
   - 建议包含：应用领域、性能指标类型
   
4. **常见问题**：
   - High: 缺少性能指标，缺少数据集说明，关键词少于4个
   - Medium: 未说明算法改进点，未说明baseline对比
   - Low: 性能指标不够具体（如只说"提高了准确率"但不说提高了多少）
"""

# ==================== 系统设计类论文摘要审查 ====================
abstract_review_system = """
【系统设计类论文摘要特殊要求】

1. **内容结构**（严格顺序）：
   - 研究背景：说明XX行业/领域需求，现有系统不足
   - 技术方案：说明系统架构（BS/CS），技术栈（前端/后端/数据库）
   - 功能模块：说明实现的主要功能（XX管理、XX管理等）
   - 测试成果：说明测试方法和测试结果
   
2. **技术栈检查**：
   - 必须明确说明前端技术（如Vue、React、JSP等）
   - 必须明确说明后端框架（如Spring Boot、Django等）
   - 必须明确说明数据库（如MySQL、MongoDB等）
   
3. **功能模块检查**：
   - 必须列举主要功能模块（至少3个）
   - 功能描述应具体（避免泛泛而谈）
   
4. **关键词要求**：
   - 不少于4个
   - 必须包含：核心技术栈名称（至少1个）
   - 建议包含：系统名称或应用领域
   
5. **常见问题**：
   - High: 技术栈不完整（缺前端/后端/数据库任一），关键词少于4个
   - Medium: 功能模块描述不清，未说明测试方法
   - Low: 表述不够具体（如"实现了管理功能"但不说具体管理什么）
"""
```

### 4.2 方案二：更细粒度的模块化设计

如果两种类型差异非常大，可以考虑为每个Agent都设计类型化的变体：

```
agent/
  prompts/
    __init__.py
    common/
      normative_common.py      # 通用规范性检查
      vision_common.py         # 通用图文检查
    algorithm/

      abstract_algorithm.py    # 算法类摘要检查
    system/
      logic_system.py          # 系统类逻辑检查
```

```python
  * **逻辑连贯性**：研究背景→技术方案→成果之间过渡是否自然，是否存在跳跃
  * **严重程度判断**：
    - High: 缺少研究背景/技术方案/成果任一部分，关键词少于4个，关键词与主题完全无关
    - Medium: 逻辑顺序混乱（如先讲技术再讲背景），关键词与主题部分不符
```
