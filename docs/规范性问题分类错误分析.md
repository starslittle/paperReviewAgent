# 规范性问题分类错误分析

## 问题现象

HTML 报告中显示"规范性一致性问题 (0)"，但实际上应该有问题被检测到，说明问题被错误分类到了其他类别。

## 原因分析

### 1. 分类逻辑的顺序问题

**代码位置：** `generate_report.py:88-106`

```python
for issue in issues:
    raw_type = issue.get("issue_type", "Unknown")
    img_id = issue.get("image_id", "")
    
    # 第一优先级：视觉问题
    if img_id or raw_type in vision_types or "一致性" in raw_type:
        vision_issues.append(issue)
    # 第二优先级：逻辑问题
    elif raw_type in logic_types:
        logic_issues.append(issue)
    # 第三优先级：规范性问题
    elif raw_type in normative_types:
        normative_issues.append(issue)
    # 兜底逻辑
    else:
        if "一致性" in raw_type or "图" in raw_type or "视觉" in raw_type:
            vision_issues.append(issue)
        elif "逻辑" in raw_type or "语言" in raw_type or "连贯" in raw_type:
            logic_issues.append(issue)
        elif "格式" in raw_type or "规范" in raw_type:
            normative_issues.append(issue)
        else:
            other_issues.append(issue)
```

**问题1：优先级顺序导致误分类**

- **第92行**：`if img_id or raw_type in vision_types or "一致性" in raw_type`
  - 如果一个问题有 `image_id`，**即使 `issue_type="规范性"`**，也会被分到 `vision_issues`
  - 如果 `issue_type` 包含"一致性"（如"目录结构一致性"），也会被分到 `vision_issues`
  - **结果**：规范性问题被误分到视觉问题

**问题2："目录结构"问题被分到 other_issues**

- LogicAgent 输出的 `issue_type="目录结构"`（`logic_agent.py:1401`）
- `normative_types = {"Format", "规范性"}`（`generate_report.py:85`）
- "目录结构"不在 `normative_types` 中
- 也不在 `logic_types` 中
- 兜底逻辑第103行：`elif "格式" in raw_type or "规范" in raw_type`
  - "目录结构"不包含"格式"或"规范"字符串
- **结果**：被分到 `other_issues`，而不是 `normative_issues`

### 2. 类型定义不完整

**当前定义：**
```python
normative_types = {"Format", "规范性"}
```

**实际应该包含的类型：**
- `"Format"` ✅
- `"规范性"` ✅
- `"目录结构"` ❌ **缺失**
- 其他可能的规范性类型（如"格式问题"、"编号问题"等）

### 3. 分类逻辑的冲突

**冲突场景示例：**

| issue_type | image_id | 实际分类 | 应该分类 | 原因 |
|-----------|----------|---------|---------|------|
| `"规范性"` | 有 | `vision_issues` ❌ | `normative_issues` ✅ | 第92行优先判断 `img_id` |
| `"目录结构"` | 无 | `other_issues` ❌ | `normative_issues` ✅ | 不在 `normative_types` 中 |
| `"目录结构一致性"` | 无 | `vision_issues` ❌ | `normative_issues` ✅ | 包含"一致性"被误判 |

## 具体问题场景

### 场景1：有 image_id 的规范性问题

```json
{
  "issue_type": "规范性",
  "image_id": "0",
  "severity": "High",
  ...
}
```

**当前行为：**
- 第92行：`if img_id` → True → 分到 `vision_issues` ❌

**应该行为：**
- 先判断 `issue_type`，如果是"规范性"，应该分到 `normative_issues` ✅

### 场景2："目录结构"问题

```json
{
  "issue_type": "目录结构",
  "severity": "High",
  ...
}
```

**当前行为：**
- 第92行：`if "一致性" in raw_type` → False
- 第94行：`elif raw_type in logic_types` → False（"目录结构"不在 logic_types 中）
- 第96行：`elif raw_type in normative_types` → False（"目录结构"不在 normative_types 中）
- 第98行：进入 else 分支
- 第103行：`elif "格式" in raw_type or "规范" in raw_type` → False（"目录结构"不包含这些字符串）
- 第106行：分到 `other_issues` ❌

**应该行为：**
- "目录结构"应该被识别为规范性问题，分到 `normative_issues` ✅

## 根本原因总结

1. **分类优先级错误**：`img_id` 的判断优先级高于 `issue_type`，导致有图片的规范性问题被误分
2. **类型定义不完整**：`normative_types` 缺少"目录结构"等类型
3. **兜底逻辑不完善**：兜底逻辑无法识别"目录结构"为规范性问题

## 解决方案建议（暂不修改代码）

### 方案1：调整分类优先级

**原则：** 先按 `issue_type` 分类，再考虑其他属性

```python
# 伪代码
if raw_type in normative_types or "目录结构" in raw_type:
    normative_issues.append(issue)
elif raw_type in logic_types:
    logic_issues.append(issue)
elif img_id or raw_type in vision_types or "一致性" in raw_type:
    vision_issues.append(issue)
```

### 方案2：扩展 normative_types

```python
normative_types = {"Format", "规范性", "目录结构", "格式问题", "编号问题"}
```

### 方案3：改进兜底逻辑

```python
elif "格式" in raw_type or "规范" in raw_type or "目录" in raw_type or "编号" in raw_type:
    normative_issues.append(issue)
```
